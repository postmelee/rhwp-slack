### 심사자 재현 순서

1. 홈페이지의 Slack에 추가 또는 Direct install URL에서 심사자가 관리하는 워크스페이스를 선택하고 설치한다.
2. 시험 채널에 rhwp를 초대하고 앱 홈 → 채널 설정 → 모든 HWP/HWPX 파일 자동 감지를 선택한다.
3. 민감정보가 없는 HWP/HWPX를 텍스트와 함께 올린다. 원본 반응과 같은 스레드의 PDF·PNG를 확인한다.
4. PDF로 보기와 이미지 클릭으로 Slack 뷰어를 열고 추가 페이지 이미지 버튼을 확인한다.
5. rhwp에서 편집 → Slack 로그인 → 브라우저 편집기에서 수정 → 편집본을 Slack에 저장한다. 같은 스레드에서 수정본과 PDF·PNG를 확인한다.
6. 채널 설정을 멘션 전용으로 바꾸고 파일과 @rhwp를 함께 보내 확인한다.
7. 접근 권한 회수·설치 제거·삭제 요청 처리는 #4의 실제 수용 결과를 연결한다. 이 문서의 절차 작성만으로 실제 검증 완료로 표시하지 않는다.

설치 실적·서로 다른 사용자·철회 검증, 약관 동의와 최종 제출은 #4에 남는다. 2026-09-22 재확인 당시 공식 기준의 활성 워크스페이스/주간 활성 사용자 요건은 기존 기록과 같았다.

### 운영 제거·재설치 수용

사용자 승인 후 Alhanguel의 공개 앱을 실제로 제거하고 같은 권한으로 재설치했다. 제거 이벤트 이후 설치 레지스트리는 `revoked`로 바뀌었고 열려 있던 합성 문서의 저장 요청은 다시 열기 안내와 함께 거절됐다. 재설치 시 새로운 설치 세대가 발급됐으며 rhwphq의 설치 세대는 유지됐다. 공개 ingress·worker는 PR #32 병합본으로 배포했고 내부 rhwp-pro 서버는 변경하지 않았다.

test·rhwp-slack 채널 재초대와 기존 자동 감지 설정은 복구했다. 이전 설치의 링크는 재로그인 후 서버에서 HTTP 400으로 거절됐으며 Chrome은 ERR_BLOCKED_BY_CLIENT 화면을 표시했다. 기존 합성 파일을 명령으로 다시 요청해 PDF·2페이지 PNG·브라우저 편집을 확인했다. 첫 저장은 내보내기 중 변경 감지 안내가 나왔고, 추가 편집 없이 재시도해 같은 카드 스레드의 편집본·PDF·PNG 생성을 확인했다. 저장된 PNG에서도 추가 문구를 직접 확인했다. 첫 저장 안내의 원인과 무효 링크 오류 화면은 개선 대상으로 남긴다.

기존 Slack 파일은 제거하지 않았다. 이번 명령 재요청·편집본 저장 검증은 새 원본 업로드 자동 감지 시험 및 실제 `file_unshared` 이벤트의 채널별 범위 검증과 구분한다.
