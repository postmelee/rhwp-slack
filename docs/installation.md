# 설치 방식 선택

2026-09-20 기준. 외부 설치형 베타는 준비 중이다. 이 문서는 설치 가능 상태와 예정 경로를 구분한다.

## 1. 서버 운영 없이 사용하고 싶은 경우 — 설치형 베타

일반 사용자는 **하나의 rhwp Slack 앱 + 우리 호스팅 + OAuth Add to Slack**을 사용한다. 사용자마다 앱을 만들거나 토큰을 운영자에게 전달하는 절차를 요구하지 않는다. [구현 이슈 #16](https://github.com/postmelee/rhwp-slack/issues/16)에서 준비 중인 흐름은 다음과 같다.

1. 공개 안내 페이지에서 **Add to Slack**을 선택한다.
2. 설치할 워크스페이스를 고르고 요청 권한을 확인한다. 조직 정책에 따라 관리자 승인이 필요할 수 있다.
3. 앱을 사용할 채널에 초대하고, 관리자 설정에서 자동 감지 또는 멘션 모드를 선택한다.
4. HWP/HWPX 업로드 후 원본 스레드의 PDF와 PNG 갤러리를 확인한다.
5. **문서 편집**을 누르면 본인과 파일의 권한을 확인한 뒤 브라우저에서 Studio를 연다. 편집본은 같은 Slack 스레드에 저장한다.

이 흐름을 제공하려면 OAuth 설치/재설치/삭제, 워크스페이스별 토큰과 작업/설정 격리, 인증된 외부 브라우저 진입 경로를 구현해야 한다. 현재 `SLACK_TEAM_ID`와 `SLACK_BOT_TOKEN`을 여러 값으로 바꾸는 것으로 해결되지 않는다. 공통 앱 ID·서명 키·OAuth 클라이언트 정보·요청 URL을 사용하되, 설치별 bot token·설정·문서/작업/세션 접근은 격리한다. 앱 설치 OAuth와 편집 사용자의 본인 인증을 구분한다. 아직 동작하지 않는 설치 링크나 고정 편집 세션 링크를 수동으로 공유하지 않는다.

Slack은 Marketplace에 없는 앱도 **unlisted distribution**으로 시험 배포할 수 있도록 지원한다. OAuth와 배포 설정을 완료한 뒤 설치 링크/버튼을 공유할 수 있다. 이는 심사 완료나 제한 없는 상업 배포를 뜻하지 않는다. [공식 배포 안내](https://docs.slack.dev/app-management/distribution/)

### 편집이 외부 브라우저에서 열리는 이유

일반 Work Object 카드와 iframe을 통한 내부 편집은 별개의 기능이다. **외부 배포 앱의 embeds는 초대제**다. 미등재 베타에도 내부 전용 앱의 예외가 적용된다고 가정하지 않는다. 해당 승인을 받기 전 외부 베타는 PDF·PNG를 Slack에서, 편집은 브라우저에서 제공한다. [Slack embeds 조건](https://docs.slack.dev/messaging/work-objects-embeds/)

## 2. 조직이 서버와 앱을 직접 관리하려는 경우 — 자체 호스팅

조직 관리자가 소스/컨테이너 접근 권한을 확보하고, **조직 소유 Slack 앱·GCP 프로젝트·Cloudflare Pages**를 구성한다. 구성원은 서버를 설치할 필요 없이 해당 조직의 봇을 사용한다.

- 현재 단일 워크스페이스 실행 구조를 재사용할 수 있다.
- 자체 소유 워크스페이스의 미배포 앱은 공식 문서상 embeds를 사용할 수 있다. 실제 조직의 앱 설정·보안 정책을 확인하고 검증한다.
- Enterprise Grid의 조직 전체 설치를 지원한다는 의미는 아니다. 현재 안내는 워크스페이스별 설치 기준이다.
- 유지보수·클라우드 비용·토큰·권한 설정은 조직 운영자가 관리한다.

자세한 구성은 [자체 호스팅 안내](self-hosting.md)를 따른다. 현재 저장소는 비공개이므로 공개 문서만으로 누구나 clone할 수 있는 상태가 아니다.

## 3. Marketplace 설치

아직 제출하지 않았다. 설치형 베타의 다중 워크스페이스 검증과 활성 설치 요건, 개인정보/지원/삭제 안내, 심사 자료를 준비한 뒤 제출한다. [진행 조건](marketplace.md)
