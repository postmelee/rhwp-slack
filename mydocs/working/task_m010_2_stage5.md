# Task #2 Stage 5 — 최대2개 업로드와 기록 직렬화

- PNG 전달을 최대1개 또는2개 실행하는 작은 작업 풀에 연결했다. `RHWP_IMAGE_UPLOAD_CONCURRENCY`는1/2만 허용하며, 실측 전 기본값은1이다. Stage7의 동일 이미지·Cloud 사양 A/B 결과로 운영값을 정한다.
- 페이지 전송이 동시에 끝나도 카드 checkpoint와 chat.update는 직렬로 수행한다. 파일ID는 페이지 번호로 정렬하며 Slack 첨부에는 연속된 앞 페이지들만 노출한다.
- 한 작업 실패 시 새 전송을 시작하지 않고 이미 시작한 작업을 모두 기다린다. 카드 잠금 해제 뒤에 늦은 전송이 기록을 덮는 상황을 막는다. 완료된 영수증은 다음 시도에서 재사용한다.
- typecheck, Slack79/79, security28/28 통과. 늦은1쪽/빠른2쪽의 완료 순서 역전에서도 실제 최대 동시2개·파일 중복 없음·갤러리1~3순서·각 공유 확인을 검사했다. 실패한 전송의 동료 작업이 끝나기 전 finish가 반환하지 않고, 실패 이후 기록도 직렬화됨을 별도로 확인했다.
- 이 단계의 지연은 합성으로 주입한 계약 검사이다. 실제 Slack 업로드의 개선 수치나2개의 운영 채택을 아직 주장하지 않는다. Stage7에서 순차/병렬 실측을 수행한다.
