# Task #5 결과 — 채널별 공유 해제 수정

## 요약

#5 · M010. file_unshared와 file_deleted의 전역 무효화를 분리했다. 공개·비공개 채널에 공유된 같은 파일에서 한 채널만 해제하면 다른 채널의 원본·수정본·유효 세션이 유지된다. 같은 채널의 루트·수정본 연결, 세션, 관측 기록 및 로컬 임시 bytes는 함께 제거한다. 현재 사용자/채널/파일 접근 검사는 유지한다.

## 변경과 검증

[Stage 1](../working/task_m010_5_stage1.md)의 수정 전 6개 실패 → [Stage 2](../working/task_m010_5_stage2.md)의 같은 6개 통과와 추가 경계 검사를 연결한다. 집중 11/11, Slack 95/95, security 53/53, typecheck 및 diff check 통과. 실제 서명 HTTP 수신·Cloud 큐 소비 경로에 합성 API 응답을 사용했다. 앱 제거/토큰 회수/재설치 관련 기존 자동 보안 회귀도 security suite에 포함된다.

공식 제품 문서는 기존 docs/development.md의 이벤트 설명만 갱신했다. 엔진·WASM·프로그램 자산·사양·비용·OAuth 권한은 변경하지 않는다.

## 수용 상태와 후속

- 충족: 최신 공유 상태로 채널별 무효화, 정상 채널 보존, 루트/수정본·세션·임시 자료 정리, 중복·지연·누락·재공유·API 장애·전역/수정본 삭제의 자동 검증.
- 미검증: 실제 Slack 파일 공유 해제 이벤트와 새 코드의 운영 배포 후 수용. 실제 앱 제거·재설치·다른 사용자 검증도 #4에 남는다.
- API가 실패하거나 shares가 불완전하면 영구 삭제하지 않는다. 접근 요청은 기존 권한 검사로 실패하고 Cloud 작업이 재시도한다. 단일 서버의 기존 즉시 ACK 때문에 Slack 자동 재전달은 보장하지 않는다.
- 이미 무효화된 과거 카드를 자동 복원하지 않는다. 재공유 후 새 메시지 메뉴 요청으로 연결을 만든다.

이 PR은 코드와 자동 검증 단계이며 #5를 닫지 않는다. 실제 시험에서는 합성 문서를 두 테스트 채널에 공유한 뒤 한 채널만 공유 해제하고 다른 채널의 원본·수정본 편집을 확인해야 한다. 실제 앱 제거/재설치는 대상 workspace의 기존 연결을 끊으므로 별도 범위를 확정한 후 실행한다.

## 승인

동일 스레드의 권한 철회 검증부터 순차 진행 지시를 적용했다. 운영 설치 제거·최종 Marketplace 제출은 수행하지 않았다. CI·검토 결과는 PR에 연결한다.
