# Task #72 수행계획 — 확정 취소와 파일 정보 안내
GitHub Issue: https://github.com/postmelee/rhwp-slack/issues/72 · M010

## 목적과 배경
#70/#71 종료 처리에 이어 확정된 무효화의 불필요한 재시도를 줄이고 files.info 실패 이유를 안전하게 안내한다.

## 범위
포함: 동일 tenant의 영속 removed/취소 상태 확인, 준비 작업과 무효화 경계 검증, 고정 원인 분류와 상태 안내, 테스트 워크스페이스 검증 후 이전 수정 포함 배포.
제외: file_not_found 단독 취소 판정, 일시 장애 영구 실패화, 권한 검사 완화, 엔진 변경, 운영 데이터 공개.

## 설계 방향
확정 상태만 작업을 정상 종료시켜 재전달과 watchdog의 추가 실패를 피한다. 시작 전과 실패 후 재확인하며 상태 조회 실패는 재시도한다. 이번 변경은 신뢰할 수 있는 기존 카드의 removed tombstone에 한정한다. 카드가 없는 prepare 요청은 원자적 취소 증거가 없으므로 기존 재시도를 유지한다. 파일 조회 원인은 코드가 생성한 allowlist만 사용하며 오류 문자열을 사용자에게 노출하지 않는다.

## 문서 위치 판단
작업 문서는 기존 mydocs/orders/plans/working/report에 둔다. 제품 문서 신설 없음. 실제 운영 입력·재현성은 비공개 ops 저장소에 분리한다.

## 예상 변경 파일
src/server/cloud/application.ts, source-failure.ts, errors/access 및 진단·안내 관련 파일, tests/slack 및 tests/security. 다른 작업자 변경 보존.

## 단계 및 검증
1. 확정 무효화 종료와 준비/삭제/경쟁/재전달/일시장애 회귀.
2. 파일 정보 고정 원인과 안내, 보안 경계 회귀.
3. 타입·전체 단위/Slack/보안/viewer/container, 실제 합성 Slack, 고정 배포 입력 재현 후 배포 확인.

## 리스크와 승인
사용자가 이 개선의 이슈 생성부터 이전 수정 포함 검증·배포까지 명시 승인했다. 취소 증거가 불확실하거나 회귀 실패시 배포하지 않는다. 실제 삭제 이벤트와 API 가시성 오류를 혼동하지 않는다.
