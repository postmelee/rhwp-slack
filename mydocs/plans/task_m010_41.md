# #41 재시도 접수·진행 표시 수행계획서

GitHub Issue: #41 · M010

## 목적과 배경
다른 사용자의 재시도는 성공했지만 버튼 응답이 404이고 실패 안내가 남았다. 동기 권한/API 처리와 카드 잠금 중 큐 발행을 분리한다. 사용자 2026-09-24 수정 승인을 전체 범위의 근거로 한다.

## 범위
포함: 서명 검증된 버튼 입력의 영속 인계, worker 권한 검사와 진행 안내, 예약/발행 분리, 중복·장애 회귀.
제외: 권한 완화, CPU·메모리·최소 인스턴스 변경, 엔진, Marketplace 최종 제출.

## 설계 방향
버튼 요청은 최소 식별자만 저장하고 큐 인계 후 응답한다. worker는 매번 권한을 확인하고 기존 카드에서 진행 안내를 갱신한다. 작업 예약을 잠금 안에서 기록하되 발행은 잠금 해제 후 수행한다. 재전달은 같은 작업을 복구한다. 안내 실패와 변환 실패를 별도로 기록한다.

## 문서 위치 판단
작업자용 계획/증적은 기존 mydocs/plans, working, report에 기록한다. 공식 제품 문서 추가는 없다.

## 예상 변경 파일
src/server/cloud/{receiver,events,application,tasks}.ts 및 관련 tests/slack 회귀.

## 단계와 검증 계획
1. 접수/작업 발행 구현과 경계 회귀.
2. 전체 typecheck·Slack/security 검증, CI 및 코드 검토.
3. 검증 보고와 공개 서비스 배포/수용. 실제 다른 계정 UI 수용은 자동 회귀와 구분한다.

## 리스크
큐 발행 실패 뒤 예약 정보만 남는 경우 재전달로 복구해야 한다. 응답만 먼저 하고 메모리에 맡기는 방식은 사용하지 않는다. 콜드 스타트 자체의 응답 지연은 이번 코드만으로 보장할 수 없다.
