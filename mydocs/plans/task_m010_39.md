# Task #39 수행계획 — 권한 철회 중 미리보기 종료

GitHub Issue: https://github.com/postmelee/rhwp-slack/issues/39
마일스톤: M010

## 목적·배경

다른 사용자 실수용에서 편집본 업로드 후 탈퇴하면 worker는 access_denied로 종료되지만 카드가 pending으로 남았다. 내부 상태 확정과 문서 접근 권한을 분리한다.

## 범위·설계

실패 메타데이터는 tenant/카드/lease/작업 세대를 검증해 먼저 확정한다. 권한 상실 시 봇의 동일 워크스페이스 채널 접근만 검사한 고정 안내로 기존 메시지를 수정한다. 파일·metadata·문서명·주소를 새로 공유하지 않는다. 재시도는 기존 권한 검사와 새 세대를 이용한다. 기존 변환·다운로드·업로드 권한 검사는 유지한다. 다른 채널·워크스페이스 전송 및 최종 심사 제출 제외.

## 예상 파일

src/server/cloud/application.ts, access.ts, document-message.ts, tests/slack/cloud-application.test.ts.

## 문서 위치 판단

계획/단계/결과는 기존 mydocs/plans·working·report, 심사 상태는 기존 docs/marketplace.md 또는 #4 기록에 연결한다. 새 공식 문서 루트 없음.

## 단계·검증

1. 실패 상태·안전한 안내 구현: 수정 전 실패/후 통과, 탈퇴·봇 제거·세대 경합·명시적 재시도 검사.
2. Linux CI와 공개 배포: 사양·IAM 유지, 기존 실패 카드·정상 카드 대조.
3. 검토·보고·PR: 검증 한계와 실제 사용자 수용 기록, 제출은 보류.

## 리스크·승인

상태 안내가 파일 재공유 경로가 되지 않아야 한다. 2026-09-23 사용자의 ‘수정을 진행해줘’와 기존 최종 제출 전까지 진행 승인으로 구현·검증·배포·PR을 이어간다.
