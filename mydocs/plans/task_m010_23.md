# Task #23 — 미저장 편집을 유지한 재인증과 저장 복구

## 범위

브라우저 편집의 세션 만료가 저장 실패로 이어져도 원래 Studio·편집 내용·저장 요청 ID/bytes를 메모리에 유지한다. 명시적 다시 로그인 버튼에서 별도 인증 창을 열고 기존 Slack OIDC 검증을 재사용한다. 원래 편집창을 새로고침하거나 문서를 다시 내려받아 덮어쓰지 않는다.

## 인증 경계

초기 인증된 metadata의 문서·사용자·워크스페이스·채널 ID를 메모리에 보관한다. 새 일회용 티켓은 정확한 편집기 origin과 열린 popup window, 임의 연결 nonce가 일치할 때만 수신한다. 교환 후 서버가 반환한 같은 identity가 확인되어야 bearer를 교체한다. 워크스페이스/사용자/문서가 다르면 원래 세션과 편집을 유지한 채 거부한다. OIDC state의 purpose·generation·nonce 및 접근 검사는 계속 수행한다. 영구 브라우저 저장소·원본 캐시·자동 로그인 갱신은 추가하지 않는다.

## 복구와 검증

팝업 차단·닫힘·시간 초과·권한 회수는 편집을 유지하고 오류 안내한다. 재인증 성공은 저장 성공이 아니므로 사용자가 같은 저장 요청을 재시도한다. 네트워크 실패 후 결과 불확실성 때문에 ID/bytes를 새로 만들지 않는다. 현재 편집의 로컬 다운로드도 별도 탈출 경로로 제공한다. 저장/인증 상태, 위조 message, 다른 사용자, 취소, 만료, 동일 ID 재시도, 새 변경 dirty 유지 및 기존 save 시나리오를 검증한다.
