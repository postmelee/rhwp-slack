# Task #34 — 첫 편집본 저장의 변경 감지 오류

GitHub Issue: [#34](https://github.com/postmelee/rhwp-slack/issues/34) · M010

## 목적과 배경

정상 네트워크에서도 합성 HWP에 한글을 입력한 뒤 첫 저장이 변경 감지로 거절되고 재시도만 성공한다. 내보내기 전후 상태 중 어떤 값이 달라지는지 재현하여 첫 저장을 복구한다. 실제 동시 편집·재시도 요청 동일성·dirty 보호는 유지한다.

## 범위

- 포함: HWP/HWPX, 실제 Studio 입력과 export 경계, 저장·다운로드·저장 확인, 자동 회귀 및 공개 편집기 수용.
- 제외: rhwp 엔진 전면 변경, #35 오류 문구, 서버 사양·권한 변경, Marketplace 최종 제출.

## 설계 방향

상태 생산 경로를 계측하고 원인 경계에서 일관된 상태·산출물을 사용한다. 변경 검사를 제거하거나 무조건 재시도하지 않는다. 개인 문서나 토큰은 계측하지 않는다.

## 문서 위치 판단

계획·단계·결과는 기존 `mydocs/plans`, `working`, `report`에 둔다. 내부 작업자용 증거이며 제품 안내를 추가하지 않는다. 필요시 `docs/marketplace.md`의 수용 상태만 기존 위치에서 갱신한다.

## 예상 변경 파일과 단계

1. 재현: `tests/viewer/save.spec.ts`와 진단 증거로 상태 변화 원인 확인.
2. 수정: `src/editor/save.ts`, 필요시 기존 `studio/vite.config.ts` overlay 및 회귀 검사.
3. 검증: HWP/HWPX, 첫 저장·동시 편집·실패 재시도, 빌드·typecheck·CI·배포 후 합성 파일 수용.

산출물은 `task_m010_34_impl.md`, `task_m010_34_stage{1,2,3}.md`, `task_m010_34_report.md`, 오늘할일이다.

## 검증 계획과 리스크

수정 전 실패/수정 후 성공을 같은 입력 경로에서 대조한다. export 중 실제 변경, 업로드 중 추가 편집, 서버 실패 후 동일 요청 재시도는 보호되어야 한다. 한글 자동 입력과 수동 IME를 구분하고 확인하지 못한 경로는 미검증으로 남긴다. 전체 엔진 업데이트로 범위를 키우지 않는다.

## 승인 근거

사용자가 PR #33 병합 → #34 수정 → #5 수용 → Marketplace 자료의 권장 순서에 “진행해줘”라고 지시했다. 해당 범위 내 조사·구현·검증을 계속한다.
