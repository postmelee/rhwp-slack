## Stage 2 — #16 OAuth·워크스페이스 격리·브라우저 편집 결과 연결

[#16](https://github.com/postmelee/rhwp-slack/issues/16)에서 하나의 배포 앱을 기준으로 구현한다. #4에서 중복 구현하지 않고 수용 결과를 연결한다. 검증된 설치 정보로 bot token을 선택하는 구조, 일회용 state, 재설치/삭제/토큰 철회, workspace별 정책·세션·큐·작업량 제한을 구현한다. 외부 편집은 단순 공개 문서 URL로 열지 않고 요청 사용자/채널/파일 권한을 확인해 ticket을 발급한다. 최소 두 workspace의 정상 접근·교차 접근 거부를 검증한다. 배포 앱의 공통 자격 증명과 설치별 토큰, 기존 내부 운영 보존/전환은 #16의 검토 가능한 구현 후 확정한다.

## Stage 3 — 초대형 베타와 조직 재현

외부 실제 설치/삭제/권한 회수/같은 스레드 저장과 비용·대기열을 검증한다. 조직 소유 계정의 Cloud Run/Pages/Slack 앱을 깨끗한 환경에 재현하고, 고정 릴리스 배포·업데이트·복구 안내를 검증한다. 자체 호스팅 안내 초안을 검증 완료로 바꾸는 근거를 남긴다.

## Stage 4 — 공개 안내와 Marketplace

실제 개인정보 처리/보관/삭제/지원 안내, 설치 페이지, 권한 사유, 심사자 시연 자료를 완성한다. 심사 대상 앱의 활성 workspace10개와 공식 요구사항을 확인한 뒤 제출한다. 외부 embeds 초대 승인과 Marketplace 심사 상태는 별개다. 실제 제출/승인 결과를 구분해 기록한다.
