수행계획: [task_m010_4.md](task_m010_4.md).

## Stage 1 — 공개 전 설치 경로와 안내 정리

- README를 현재 내부 기능·준비 중인 설치형 베타·조직 자체 호스팅으로 정리한다.
- 사용자가 선택한 외부 베타의 PDF·PNG Slack 보기/브라우저 편집을 기록한다. 내부용 앱의 Slack 편집을 유지한다.
- 제품 docs/에 설치, 자체 호스팅, Marketplace 요건을 둔다. 실제 동작하지 않는 설치 버튼이나 원클릭 배포를 제공한다고 쓰지 않는다.
- Markdown 상대 링크·실제 명령/설정·bootstrap/HTTPS manifest 출력을 확인한다.
- 문서만의 PR로 검토하며 #4 전체를 닫지 않는다.

## Stage 2 — OAuth·워크스페이스 격리·브라우저 편집

검증된 설치 정보로 bot token을 선택하는 구조, 일회용 state, 재설치/삭제/토큰 철회, workspace별 정책·세션·큐·작업량 제한을 구현한다. 외부 편집은 단순 공개 문서 URL로 열지 않고 요청 사용자/채널/파일 권한을 확인해 ticket을 발급한다. 최소 두 workspace의 정상 접근·교차 접근 거부를 검증한다. 별도 외부 앱의 자격 증명과 연결 설정은 검토 가능한 구현 후 확정한다.

## Stage 3 — 초대형 베타와 조직 재현

외부 실제 설치/삭제/권한 회수/같은 스레드 저장과 비용·대기열을 검증한다. 조직 소유 계정의 Cloud Run/Pages/Slack 앱을 깨끗한 환경에 재현하고, 고정 릴리스 배포·업데이트·복구 안내를 검증한다. 자체 호스팅 안내 초안을 검증 완료로 바꾸는 근거를 남긴다.

## Stage 4 — 공개 안내와 Marketplace

실제 개인정보 처리/보관/삭제/지원 안내, 설치 페이지, 권한 사유, 심사자 시연 자료를 완성한다. 심사 대상 앱의 활성 workspace10개와 공식 요구사항을 확인한 뒤 제출한다. 외부 embeds 초대 승인과 Marketplace 심사 상태는 별개다. 실제 제출/승인 결과를 구분해 기록한다.
