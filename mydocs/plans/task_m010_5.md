# Task #5 — 채널별 문서 공유 해제

GitHub Issue: [#5](https://github.com/postmelee/rhwp-slack/issues/5) · M010

## 목적·배경

한 채널의 file_unshared 이벤트가 다른 채널의 동일 파일·수정본 카드까지 무효화하는 결함을 재현하고 수정한다. 최초 동료 접속 실패와의 인과관계는 확정하지 않는다. [Slack 이벤트 문서](https://docs.slack.dev/reference/events/file_unshared/)의 payload에는 채널이 보장되지 않으며 files.info로 추가 정보를 확인하도록 안내한다.

## 범위

Cloud Run/단일 서버의 공유 해제·전역 파일 삭제, 루트/수정본·세션·관측 기록·로컬 준비 자료 무효화를 포함한다. 현재 권한 검사를 유지하고 불완전한 공유 정보나 API 장애를 영구 삭제의 근거로 삼지 않는다. 설치 제거·재설치는 #4의 별도 실제 수용이며, 이번 코드 변경으로 완료를 주장하지 않는다. 운영 앱 삭제·사용자 파일 삭제·새 OAuth 권한·최종 심사 제출은 제외한다.

## 설계 방향

file_deleted는 기존 전역 무효화를 유지한다. file_unshared는 최신 files.info의 완전한 공유 정보를 한 번 조회해 채널별로 남은 공유를 판정한다. 남아 있는 채널은 보존하고 사라진 채널의 카드·세션·준비 자료만 무효화한다. API 실패/불완전 응답에서는 카드를 영구 제거하지 않으며 매 요청의 authorizeFile 검사가 접근을 거절한다. Cloud 작업은 재시도한다. 이미 제거된 카드는 공유 복구로 되살리지 않고 새로운 요청으로 생성한다.

## 변경 파일·단계

1. Stage 1: tests/slack·security에 두 채널 재현과 삭제·중복·복구·장애 경계 검사를 추가하고 수정 전 실패를 기록한다.
2. Stage 2: src/server의 공유 상태 판정 및 로컬/Cloud 경로를 수정하고 집중 검사·타입 검사를 수행한다.
3. Stage 3: Slack/security 전체 검사·CI·리뷰와 docs/development.md·최종 보고서를 정리한다. 실제 Slack 공유 해제 관측이 없으면 미검증으로 남기고 #5를 닫지 않는다.

## 검증 계획·위험

서명된 Bolt 요청부터 Cloud 작업까지, 공개/비공개 채널, 루트/수정본, 기존 세션, 이벤트 중복·지연·누락, 재공유, 파일 삭제, API 장애를 검사한다. 불완전한 files.info로 권한이 남은 카드를 지우지 않는 것이 핵심이다. 실제 설치 제거는 설치된 사용자에게 영향을 주므로 준비된 검증 계획을 별도로 확인한다.
