# Task #17 — 컨테이너 시간 초과 진단과 실패 증거 보존

Issue: [#17](https://github.com/postmelee/rhwp-slack/issues/17). M010.

## 목적·배경

PR #15 push run 35467825627 attempt 1의 90초 초과는 원인 미확정이다. 동일 head 재실행과 PR CI는 통과했지만 tmpfs 안의 trace가 삭제돼 실패 단계를 복원할 수 없다. 사용자 지시로 원인 조사를 계속하며 재발 시 진단 가능한 경로를 만든다.

## 범위·설계

합성 Slack/문서만 사용하는 통합 테스트에 단계별 시간과 Playwright step을 추가한다. CI가 전용 출력 디렉터리를 bind mount하여 실패 자료를 수집한다. smoke 종료 성공 여부와 관계없이 cgroup memory.events/peak/cpu.stat을 기록한다. 제품 코드, 서버 사양, 90초 제한은 바꾸지 않는다. 최초 실패를 추정으로 해결 처리하지 않는다.

## 문서 위치 판단·예상 파일

작업 산출물은 `mydocs/plans`, `working`, `report`, `orders`에 둔다. 제품 기능 변화가 없어 공식 사용자 문서 변경은 없다. 변경 소스는 `tests/viewer/slack-flow.spec.ts`, `scripts/container-smoke.mjs`, `.github/workflows/ci.yml`이다.

## 단계·검증

1. 단계별 시작/성공/실패 시간 기록: typecheck 및 기존 viewer flow.
2. 실패 출력과 cgroup 보존: Node 구문 검사, Linux 제약을 유지한 CI.
3. 원시 증거와 한계 정리: PR 최종 head CI 및 report.

## 리스크와 승인

추적 자료는 합성 입력만 포함한다. 최초 원인은 과거 artifact 소실로 계속 미확정일 수 있다. 사용자 ‘권하는 순서대로 진행’ 및 시간 초과 조사 요청 범위 내에서 진행한다.

## 2026-09-20 재발 조사 계획 (승인된 후속)

사용자가 남은 안정성 작업의 순차 진행을 승인했다. PR #19 실행 35486142804에서 편집/저장/재열기 이후 stop-receiver가 82,332ms 대기했다. Bolt stop은 node HTTP server.close 완료를 기다리며 Playwright의 page/context는 테스트 finally 이후에 닫힌다. 열린 브라우저 연결이 종료를 막는지 실행으로 확인한다.

범위: 테스트가 소유한 브라우저 자원과 수신 서버의 종료 순서, 직접 TCP 연결 반례, smoke 회귀. 제품의 요청을 강제 중단하거나 90초 제한/컨테이너 조건을 바꾸지 않는다. 새 제품 문서는 없고 조사·검증 증거는 기존 mydocs/working/report에 기록한다.

추가 단계: Stage4 재현과 연결 소유권 확인 → Stage5 종료 순서 수정과 회귀 → Stage6 Linux CI·검토·병합. 최초 #15는 당시 trace 부재로 동일 원인이라고 단정하지 않는다.
