# Task #35 수행계획 — 무효 편집 링크 복구 안내

GitHub Issue: https://github.com/postmelee/rhwp-slack/issues/35
마일스톤: M010 (공개 베타 작업 문서 계열; 이슈 milestone 미지정).

## 목적·배경

앱 재설치 전 링크가 OIDC 뒤 HTTP 400과 Chrome 오류 화면을 보였다. 첫 저장 오류 #34와 별개이며 네트워크 문제로 단정하지 않는다. 기존 callback은 인증 관련 query가 있는 주소에 text/plain 400을 반환하고 모든 실패를 합친다.

## 범위

로그인 만료·문서 연결 사용 불가·인증 실패·사용자 취소를 고정된 안내로 구분한다. callback의 코드를 정적 결과 주소로 가져가지 않고 안전한 같은 origin 결과 경로로 303 이동한다. 실제 접근 거절, JWT·state·설치 세대·최신 문서 권한 검사는 유지한다. 재설치/타 사용자 구별을 위한 새 개인정보는 표시하지 않는다. 앱 재설치를 반복하거나 기존 문서를 삭제하지 않는다.

## 설계 방향

신뢰할 수 있는 서버 단계에서 분류한 오류 enum만 결과 URL에 둔다. 알 수 없는 값은 일반 실패로 처리하고 request 값·예외 문자열을 HTML에 반영하지 않는다. 로그인 만료는 일회용 state 단계, 문서 연결 오류는 신원 검증 뒤 문서/설치 검증 단계에서 구분한다. 브라우저 오류의 정확한 확장 프로그램 원인은 관측만으로 확정하지 않는다.

| mydocs/plans·working·report | 작업 증거·내부 | 기존 M010 단계 기록 유지 |

## 예상 변경·잠정 단계

1. Stage 1: signin·browser-routes 및 고정 오류 페이지, 보안 회귀. callback 거절 시 발급 없음/민감 값 미노출 검증.
2. Stage 2: 로컬·Linux·화면 검증, 공개 ingress 배포. 기존 정상 경로와 오래된 연결을 대조.
3. Stage 3: 실제 수용 결과·한계 기록, PR 검토·병합, #4 제출 전 체크 정리.

## 검증 계획

기존 OIDC 보안 검사 유지, GET/POST 오류 redirect·HTML·CSP·no-store·no-referrer·코드/토큰 미반영, 취소와 만료 구분. 운영의 오래된 링크와 정상 새 링크를 각각 확인한다. 실제 다른 사용자 탈퇴는 협력자 없으면 미검증으로 남긴다.

## 리스크·승인

모든 오류를 재설치 때문이라고 설명하지 않는다. 권한 복구나 자동 설치를 수행하지 않는다. 사용자의 2026-09-23 ‘최종 제출 전까지 진행’으로 구현·검증·배포·PR 절차를 진행하고 Marketplace 최종 제출은 제외한다.
