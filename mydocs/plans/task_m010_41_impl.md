# #41 구현계획서

사용자의 수정 지시에 따라 수행계획의 범위로 진행한다.

## Stage 1 — 영속 접수와 잠금 분리
- receiver의 재시도/추가 이미지 버튼을 CloudEvents 입력으로 인계한다. action_ts·사용자·카드·메시지 조합으로 중복을 구분한다.
- tasks 예약과 dispatch를 분리한다. 카드에는 작업 ID와 접수 식별자를 기록하고 잠금 해제 뒤 발행한다.
- worker에서 권한 확인 및 카드 진행 표시를 수행한다. 표시 실패는 안전한 오류 코드로 기록하고 등록된 작업을 계속 발행한다.

## Stage 2 — 검증
서명 HTTP 회귀에서 느린 Slack API가 접수 응답을 막지 않는지 확인한다. 중복 접수·발행 실패 후 재전달·다른 사용자·잠금 해제·표시 실패를 검사한다. 전체 typecheck/Slack/security와 Linux CI를 실행한다.

## Stage 3 — 공개 배포 및 보고
코드 검토 후 공개 ingress/worker만 같은 이미지로 배포한다. 이전 리비전을 기록하며 권한/사양 변경은 하지 않는다. 실제 Slack 수용과 자동 회귀를 구분해 최종 보고한다.
